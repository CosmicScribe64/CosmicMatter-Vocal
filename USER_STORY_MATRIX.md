# VocalRack V1 user-story acceptance matrix

This matrix is the release gate from a user's point of view. A story is complete only when its automated checks pass **and** the indicated behavior has been exercised in the installed plugin inside real VCV Rack. The final evidence and observed results are recorded in `test-artifacts/e2e/TEST_REPORT.md`; generated helper modules are test-only and are not shipped.

## Final in-depth Rack journey

The real-Rack run must traverse the stories rather than testing them as disconnected screenshots:

1. Install the candidate package into an isolated Rack user directory and add VOCAL.
2. Inspect the compact panel, piano labels, lyrics, phoneme/dynamics lanes, status, ports and tooltips.
3. Open the module menu; import representative USTX, legacy UST and MIDI material; review track selection and compatibility reporting.
4. Open the full editor; add/select/move/resize/copy/delete notes, edit a lyric and alias, drag phoneme START/XFADE timing and use exact/reset controls, create a continuation note, modify pitch/dynamics/vibrato, undo/redo, create/name a section, navigate, zoom, fit and close/reopen the editor.
5. Exercise internal Play/Pause/Reset/Loop/Song/Section and patch external Clock/Run/Reset/Trigger plus expression CV.
6. Patch VOICE OUT both dry and through a stock reverb into the audio path. Capture and measure the dry voice, changed wet signal and decay tail.
7. Save the `.vcv`, quit/reopen Rack, verify state and score visually, and replay the same material.
8. Run a complete multi-bar song to END with zero underruns, while other independent VOCAL instances exercise one-shot, loop, clock and CV cases.
9. Archive the patch, screenshots, WAVs, Rack log, timing/counter JSON and signed-off result table under `test-artifacts/e2e/`.

The completed installed-plugin result table and real-pointer evidence index are in `test-artifacts/user-journey/USER_STORY_REPORT.md`.
